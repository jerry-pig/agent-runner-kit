# 双数据源活动归并与日志规则

1. 先按运动员本地日期查各平台活动，记录项目、来源、开始时间、时长、距离和平台活动 ID；跨午夜时检查相邻日期。
2. 确认 Intervals.icu 的来源和 `external_id` 与 COROS 的活动 ID 对应时，两个平台代表一次活动，仅计一次。ID 不匹配时结合时间、项目、距离核对；无法判断时保留差异并标 `needs_review`。
3. MyWhoosh 等平台可能反复使用同一 FIT 文件名，不能只凭 `external_id` 合并；连续但不重叠的多段可能是真实的多个活动。双练保留每项活动的独立 ID。
4. 跑步距离、骑行分钟和虚拟距离分列。不同平台负荷模型不直接相加；CTL／ATL／TSB 是模型，骑行 FTP 未校准时功率分区和负荷也存在不确定性。
5. 记录数据来源、抓取时间和缺失字段；自行报告、设备值、训练计划及 AI 推断分开。历史记录纠错时保留可追溯说明。
6. 以双练综合页或单项页之一作为计量来源；仅供链接的页面不再填写可汇总距离。当前模板与 Dataview **不自动按活动 ID 去重**，周结算仍需核对。

Intervals.icu API 使用 Basic Auth：用户名为字面 `API_KEY`，密码为个人 API key。凭证只存本地受保护配置，不写进 Markdown、日志、截图或 Git；具体配置以实际安装的工具文档为准。
